# ChessDemake — FPGA 西洋棋對戰系統

## 專案簡介
硬體設計與實驗（Hardware Design Lab）課程專案，以 Verilog 在 Xilinx FPGA（Basys 3）上實作可雙人對戰的西洋棋系統。二人合作完成，完成度約 90%。

## 開發環境
- Xilinx Vivado 2019.2
- Verilog HDL
- Digilent Basys 3 開發板（兩片，master／slave 架構）

## 功能
- **VGA 顯示**：棋盤與棋子畫面輸出至螢幕
- **PS2 鍵盤操作**：WASD／方向鍵移動游標，Enter／空白鍵選取
- **棋子移動規則**：士兵、騎士、城堡、主教、皇后、國王各自的合法移動與阻擋判斷
- **升變（Promotion）**：士兵抵達底線後可選擇升變棋種
- **將軍偵測**：以國王位置反向檢查各棋種的攻擊路徑
- **回合輪替與計時器**：七段顯示器顯示剩餘時間，落子後加時
- **勝負判斷**：國王被吃或時間耗盡即結束，並於雙方板上顯示 WIN／LOSE
- **音效與 LED 指示**：移動、升變、將軍、結束各有對應音效；LED 以不同閃爍型態提示當前狀態
- **雙板連線**：master 板透過 7 條單向訊號將回合、暫停、重置、將軍、勝負等狀態傳給 slave 板，供另一位玩家顯示

## 技術重點：棋盤狀態編碼

棋盤以 64 個 entry 的陣列儲存，每格僅用 **6 bits** 表示。這 6 個 bit 同時承擔兩件事：

- **高 3 位**：棋子種類
- **低 3 位**：棋子顏色（0 黑／1 白）、格子背景（0 綠／1 白）、是否被選取

所有棋子素材拼成一張 240×210 的圖（8×7 張 30×30 的小圖）。由於素材在圖中的排列順序與上述編碼一致，這 6 個 bit 可以直接拆成 `y = info[5:3]`、`x = info[2:0]` 當作座標去定址，不需要任何查表或搜尋，取圖成本為 O(1)。

這個設計帶來兩個額外好處：

1. **狀態切換只需單 bit 運算**：例如選取某格只要 `board[cursor] | 6'b000_001`，取消選取則是 `& 6'b111_110`。因為這些 bit 本身就是定址用的 bit，翻轉後定址結果自動指向素材圖中「被選取」版本的圖，不需額外的解碼邏輯。
2. **規則判斷可用遮罩完成**：將軍偵測時只要遮掉顏色與背景等不相關的位元，即可用單一比較判斷棋種，例如 `(board[i] & 6'b111100) == 6'b101000` 判斷該格是否為黑色國王。

## 已知未完成項目
- **將死（Checkmate）**：需窮舉所有己方棋子的可行走法才能判定，評估工作量過大，改以「國王被吃掉」作為結束條件
- **逼和（Stalemate）**：原因同上
- **吃過路兵（En passant）**：需額外記錄士兵是否為首次移動兩格
- **王車易位（Castling）**：需建立在將軍判斷之上，完成將軍偵測後已無餘裕實作

## 分工
本人負責：將軍偵測、VGA 顯示、素材整理與編碼、勝負判斷、棋子移動（士兵／騎士／國王）
組員負責：音效、升變、游標移動、回合輪替、棋子移動（城堡／主教／皇后）

## 開發過程中的主要困難
將軍偵測的邊界條件。最初以一維座標（0–63）直接加減來檢查周圍格子，例如以 `king_position - 17` 檢查騎士的左上方，並僅驗證結果是否落在 0–63 範圍內。但這種寫法在棋盤邊緣會失效：位置小於 8 時再減 8 會因為只有 6 bits 而繞回大數值，仍落在合法範圍內；主教的右上方 `-7` 在該列最右側時也會錯誤地偵測到下一列的最左格。

問題在於大部分測試情境都不會觸發，直到所有功能完成後才出現難以重現的異常，因此耗費了整個專案最多的除錯時間。最終將所有判斷改為先分離 x、y 兩個維度、確認各自在範圍內後才做位移，才徹底解決。
